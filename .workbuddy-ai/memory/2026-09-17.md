# 2026-09-17

## Built: Real-Time Object Detection and Scene Analytics Using YOLO11

Replaced the earlier image/video/batch-processing spec with the final webcam
real-time spec. Built the project from scratch in this directory.

### What was created
- `app/` — 9 modules, ~3,355 lines: `camera`, `detector`, `analytics`,
  `controls`, `renderer`, `cli`, `utils`, plus `__init__`/`__main__`.
- `tests/` — 8 files, 231 tests, all passing under plain `pytest -q`.
- `docs/` — `architecture.md`, `workflow.md`, 5 Mermaid diagrams.
- `README.md` (31 sections), `statement.md`, `VALIDATION.md`,
  `examples/commands.md`, `requirements.txt`, `pyproject.toml`, `.gitignore`,
  `LICENSE` (MIT + third-party AGPL notice for Ultralytics).

### Key design decisions
- **Lazy heavy imports.** `ultralytics`/`torch`/`cv2` are imported inside
  functions, so `app.utils`/`app.analytics`/`app.controls` load with zero heavy
  deps. Verified: importing those three pulls in no `cv2`/`torch`/`ultralytics`/
  even `numpy`. This is what makes the unit suite hardware-free and fast.
- **Structural typing for analytics.** `app/analytics.py` accepts any object with
  `class_name`/`confidence` (a `Protocol`), so it never imports `detector.py`.
- **Headless validation path.** `--no-display` + `--max-frames N`, plus the
  `Camera` accepting a video-file path, allow the whole pipeline to be verified
  without a webcam. This was essential — no webcam exists on this machine.
- **Marked tests.** `slow` (loads real YOLO11n) and `display` (needs a webcam) are
  deselected by default via `addopts = "-ra -m 'not slow and not display'"` in
  `pyproject.toml`, so `pytest -q` works anywhere.
- **Silence native OpenCV stderr** via an `os.dup2` context manager in
  `camera.py`, otherwise "OpenCV: camera failed to properly initialize!" clutters
  our own clean error messages.

### Bugs found and fixed during validation
1. `Camera(source=Path(...))` left `self.source` as a `PosixPath`; `is_file_source`
   returned `False` and `int(PosixPath)` raised `TypeError`. Fixed by adding
   `Camera._normalise_source()`.
2. `Detector.load()` treated a bare official checkpoint name (`yolo11n.pt`) as a
   missing local file. Fixed: only treat it as a local path when a directory
   component is present or the file actually exists.
3. A test asserted the wrong expectation for `filter_by_confidence` (fixture
   confidences are 0.91/0.74/0.62, threshold 0.75 keeps only 1). Test fixed, not
   the code.

### Verified
- `pytest -q` → **231 passed, 3 deselected**.
- `pytest -q -m slow` → **2 passed** (real YOLO11n loads, 80 classes).
- All invalid-CLI cases → exit code 2 with clear messages, no traceback.
- No webcam → clean error, exit 1. `--list-cameras` → no usable camera.
- Full pipeline against a synthetic video: 40 frames, real detections
  (`frisbee`/`sports ball`), 56.1 avg FPS on MPS, `session_summary.json` written.
- Controls driven through the real loop: snapshot JPEG (45 KB, box + overlay
  visually confirmed) and recording MP4 (17 frames, 640x480) both produced.
